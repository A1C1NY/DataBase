## 6. ORM 与真实数据库结构比较

使用 Alembic 的 `compare_metadata()` 将真实数据库反射结果与 `Base.metadata` 比较：

```python
from alembic.autogenerate import compare_metadata
from alembic.migration import MigrationContext

import app.models
from app.db.base import Base
from app.db.session import engine

with engine.connect() as connection:
    context = MigrationContext.configure(
        connection,
        opts={
            "compare_type": True,
            "compare_server_default": True,
        },
    )
    differences = compare_metadata(context, Base.metadata)
    for difference in differences:
        print(difference)
```

最初发现三处布尔默认值差异。原因是指南使用 `DEFAULT TRUE`，MySQL 实际保存并通过
`SHOW CREATE TABLE` 返回 `DEFAULT '1'`。ORM 已将 `users`、`lines`、`stops` 的
`is_active` 默认值调整为 `1`，消除该差异。

调整后 Alembic 仅报告以下同一索引的一删一加：

```text
remove_index: idx_arrival_stop_time (stop_id, collected_at)
add_index:    idx_arrival_stop_time (stop_id, collected_at DESC)
```

这两项不是实际结构差异。SQLAlchemy 2.0.51 的 MySQL Inspector 反射该索引时只返回
列名，不返回第二列的降序信息，因此 Alembic 无法识别真实数据库中已有的 `DESC`。

## 7. 真实索引方向复核

在 MySQL 中直接执行：

```sql
SHOW INDEX FROM arrival_infos
WHERE Key_name = 'idx_arrival_stop_time';
```

重点检查：

```text
Seq_in_index = 1, Column_name = stop_id,      Collation = A
Seq_in_index = 2, Column_name = collected_at, Collation = D
```

其中 `A` 表示升序，`D` 表示降序。本次数据库返回 `collected_at` 的
`Collation = D`，证明真实索引与指南中的定义一致：

```sql
KEY idx_arrival_stop_time (stop_id, collected_at DESC)
```

因此 Alembic 的两条索引差异应作为已确认的反射误报处理，不能把 ORM 中的 `DESC`
删除，否则下一次迁移生成的新数据库会偏离构建指南。

## 9. 事务回滚式真实数据库冒烟测试

测试在一个事务中完成，最后始终执行 `ROLLBACK`。测试前后分别统计 `users`、
`lines`、`stops` 和 `ingestion_runs` 的记录数，确保测试未留下数据。

### 9.1 插入测试关系

按外键依赖顺序临时插入：

1. 中文用户名到 `users`；
2. 中文线路名到 `lines`；
3. 中文站名和经纬度到 `stops`；
4. 线路站序到 `line_routes`；
5. 用户收藏到 `favorite_stops`；
6. 查询日志到 `query_logs`；
7. 采集运行到 `ingestion_runs`；
8. 到站快照到 `arrival_infos`；
9. 调度快照到 `dispatch_schedules`；

随后关联 `arrival_infos`、`lines` 和 `stops`，实际返回：

### 9.2 验证重复快照唯一约束

这证明 `uq_arrival_run_line_stop` 正常工作。

### 9.3 验证用户删除策略

在事务内删除测试用户，然后检查：


对应行为为：

- `favorite_stops.user_id` 使用 `ON DELETE CASCADE`，收藏记录被删除；
- `query_logs.user_id` 使用 `ON DELETE SET NULL`，查询日志得到保留。

### 9.4 回滚和数据恢复确认


```text

```

测试前后记录数完全一致，未留下测试用户、线路、站点、快照或调度数据。
